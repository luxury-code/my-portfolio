## 2. Hero 섹션 — `AURORA`

> 참고 레퍼런스: https://nexstudio.tech/

### 2-1. 헤드라인 (스토리텔링형)

```
어두운 화면 위에
빛이 어떻게 움직이는지
계속 궁금했습니다.
```

**서브라인**

```
프론트엔드 개발자 손은솔 — 디자인과 대화로 화면을 만듭니다.
```

**하단 안내**

```
↓  마우스를 움직여 보세요
```

#### 설계 의도

- NexStudio는 `Digital / Design / Experience` — **명사 3개의 선언형**
- 이쪽은 **문장으로 된 스토리텔링형**. 요청하신 방향이면서 동시에 레퍼런스와 겹치지 않음
- "궁금했습니다"라는 **과거형 고백**이 신입의 포지션과 정직하게 맞음 (전문가 코스프레 X)
- 마지막 줄이 **인터랙션 유도**로 이어짐 → 방문자가 즉시 참여

#### 대안 헤드라인

| 안 | 내용 | 톤 |
|---|---|---|
| **A (채택)** | 어두운 화면 위에 / 빛이 어떻게 움직이는지 / 계속 궁금했습니다. | 서사적 |
| B | 화면 위에 / 빛을 그립니다. | 간결 |
| C | 빛이 어디로 갈지는 / 당신이 정합니다. | 인터랙션 직결 |

### 2-2. 시각 컨셉 — 오로라 + 별

**레이어 구조 (아래에서 위로)**

```
┌─ L5  텍스트 레이어 ─────────────── 헤드라인 · 서브라인 · 스크롤 유도
├─ L4  비네트 ─────────────────────  가장자리 어둡게 (radial-gradient)
├─ L3  별 레이어 ────────────────── <canvas> · 마우스 반응 · 40~140개
├─ L2  오로라 레이어 ────────────── CSS 그라디언트 3겹 · blur · 마우스 추종
└─ L1  밤하늘 베이스 ────────────── #0B0B0B 단색
```

### 2-3. 오로라 스펙 — CSS로 구현 (WebGL 아님)

#### 왜 CSS인가

현재 번들이 이미 789KB입니다. `three.js`를 얹으면 약 +600KB입니다.
CSS `radial-gradient` + `filter: blur()` + CSS 변수 조합이면 **추가 용량 0KB**로 충분히 아름답습니다.
성능 · 용량 · 유지보수 모두 유리합니다.

#### 색상 구성 (기존 팔레트 그대로)

| 레이어 | 색 | 토큰 | 역할 |
|---|---|---|---|
| 코어 | `#DDFF50` | `primary` | 오로라 중심의 가장 밝은 띠 |
| 확산 | `#ECFF9B` | `primaryLight` | **연노랑** — 요청하신 핵심 색 |
| 중간 | `#7FE0C1` | `accent.mint` | 초록빛 전이 |
| 끝단 | `#CAB8F6` | `accent.lavender` | 보랏빛 잔광 |
| 배경 | `#0B0B0B` | `secondary` | 밤하늘 |

#### 동작 원리

```
1. mousemove → 좌표를 0~1로 정규화
2. requestAnimationFrame 안에서 lerp(현재값, 목표값, 0.06) 으로 부드럽게 추종
   → 마우스를 정확히 따라가지 않고 "느리게 끌려오는" 점성 있는 느낌
3. CSS 변수 --mx, --my 에 주입
4. 오로라 3겹이 각각 다른 배율(0.6 / 1.0 / 1.4)로 이동
   → 시차(parallax)로 깊이감 발생
5. 동시에 @keyframes 로 18~26초 주기의 느린 자체 일렁임
   → 마우스를 안 움직여도 살아있음
```

#### 구현 스케치

```css
.aurora {
  position: absolute;
  inset: -20%;
  filter: blur(80px);
  opacity: 0.55;
  background:
    radial-gradient(45% 35% at calc(30% + var(--mx) * 18%) calc(35% + var(--my) * 14%),
      #DDFF50 0%, transparent 62%),
    radial-gradient(50% 40% at calc(62% - var(--mx) * 12%) calc(28% + var(--my) * 20%),
      #ECFF9B 0%, transparent 66%),
    radial-gradient(55% 45% at calc(48% + var(--mx) * 24%) calc(52% - var(--my) * 16%),
      #CAB8F6 0%, transparent 70%);
  animation: aurora-drift 22s ease-in-out infinite alternate;
}
```

### 2-4. 별 스펙 — `<canvas>` 2D

**별 하나의 상태**

```js
{ x, y, r: 0.4~1.6, baseAlpha, twinkleSpeed, vx, vy }
```

**마우스 영향 — "밀어내기" 방식**

```
마우스로부터 반경 140px 이내의 별
  → 마우스 반대 방향으로 최대 18px 밀려남
  → 손을 떼면 원위치로 복귀 (스프링 감쇠 0.92)

동시에 전체 별이 매우 느리게 좌→우 드리프트 (0.02px/frame)
```

빛(오로라)은 **마우스를 따라오고**, 별은 **마우스를 피합니다.**
두 레이어가 반대로 움직여 깊이감과 신비감이 동시에 생깁니다.

#### 성능 가드레일 (필수)

| 조건 | 처리 |
|---|---|
| 데스크톱 | 별 140개 |
| 모바일 / `pointer: coarse` | 별 **40개** + 마우스 반응 OFF, 자동 드리프트만 |
| `prefers-reduced-motion: reduce` | **애니메이션 전면 정지**, 정적 오로라만 |
| `document.hidden` (탭 비활성) | `cancelAnimationFrame` — 배터리 보호 |
| `devicePixelRatio` | 최대 2로 제한 (레티나 과부하 방지) |
| Hero가 뷰포트 밖 | `IntersectionObserver`로 rAF 중단 |

> **이 가드레일은 선택이 아니라 필수입니다.**
> 화려한 히어로가 저사양 폰에서 버벅이면, 그 순간 "성능을 모르는 개발자"로 평가됩니다.
> 반대로 가드레일이 코드에 있으면 **그 자체가 실력 증명**이고, 면접에서 말할 거리가 됩니다.

### 2-5. 로딩 연출 (선택)

NexStudio의 `000` 카운터, Gil Huybrecht의 `0%` 로더처럼 짧은 인트로를 둡니다. 단, **1.2초 이내**로 제한합니다.

```
        S O L
   ─────────────────
   빛을 켜는 중  ·  0%  →  100%
```

- 카운터가 100%에 닿으면 오로라가 **아래에서 위로 피어오르며** 등장
- **재방문 시 생략** (`sessionStorage`) — 매번 기다리게 하지 않기

### 3-2. 4개 스토리 블록 초안

#### 01 ─ 시작

> **"나를 간략히 표현하는 웹사이트가 갖고 싶었습니다."**
>
> 그 문장 하나로 시작했습니다. 처음엔 HTML 파일 하나였고, 지금은 데이터베이스와 배포 파이프라인이 붙었습니다. 이 사이트는 그 과정이 쌓인 결과물입니다.

#### 02 ─ 태도

> **"즐겁게 디자인하기"**
>
> 화면이 예뻐지는 순간이 재미있어서 계속하게 됐습니다. 색을 고르고, 여백을 재고, 버튼이 눌리는 느낌을 다듬는 일에 시간을 씁니다. 이 즐거움이 오래 갈 수 있는 이유라고 생각합니다.

#### 03 ─ 화면 밖의 나

> `#줌바` — 일주일에 몇 번은 몸을 씁니다. 앉아만 있으면 아이디어도 굳더라고요.
>
> `#AI` — 요즘 가장 궁금한 것. 이 포트폴리오도 AI와 함께 만들었습니다.

#### 04 ─ 가는 방향

> **시니어 프론트엔드 개발자**
>
> 지금은 화면을 만듭니다. 앞으로는 **화면을 만드는 방식**을 만들고 싶습니다. 디자인 시스템, 컴포넌트 구조, 팀이 함께 쓰는 규칙 같은 것들이요.

> **04가 이 섹션의 승부처입니다.**
> "시니어가 되고 싶다"는 누구나 씁니다.
> **"화면 → 화면을 만드는 방식"** 처럼 무엇이 달라지는지를 구체적으로 쓰면 성장 방향이 있는 사람으로 읽힙니다.

```
║  기록하는 자리입니다. 다음에 오시면 등급이 바뀌어 있을 거예요. ║
╚══════════════════════════════════════════════════════════════╝
```

### 4-2. 상세 스펙

| 요소 | 내용 |
|---|---|
| **메뉴명** | 기술명 (영문, 세리프 대문자) |
| **설명** | 요리 은유로 한 줄 (한글, 작게) |
| **점선 리더** | 메뉴판의 시각적 상징. `flex: 1` + `border-bottom: 1px dotted` |
| **"가격"** | 숙련도 `상` / `중` / `하` — **기울임체(italic) + 모노 폰트** |
| **⟨n⟩** | 해당 기술로 만든 **프로젝트 수** |
| **호버** | 배경에 그 기술 관련 프로젝트 썸네일이 **흐릿하게 페이드인** (Gil 패턴) + 해당 행만 라임으로 하이라이트 |

### 4-3. 왜 이게 강력한가

1. **"하"를 숨기지 않는 정직함**
   대부분의 신입 포트폴리오는 프로그레스바를 70~80%로 채웁니다. 아무도 안 믿습니다.
   **전부 '하'라고 쓰는 순간 나머지 모든 말의 신뢰도가 올라갑니다.**

2. **성장이 보이는 UI**
   Supabase에 저장하면 **코드 배포 없이 등급 변경 가능**.
   방문자가 다시 왔을 때 실제로 바뀌어 있으면 그 자체가 이야기가 됩니다.

3. **프로젝트 수와 연결**
   숙련도 주장에 **근거(프로젝트 수)를 붙이는** 구조.
   `Node.js ⟨0⟩`은 "아직 안 써봤다"는 정직한 신호이고, 이게 오히려 신뢰를 만듭니다.

4. **기억에 남음**
   채용 담당자가 하루에 포트폴리오 20개를 봅니다. "메뉴판으로 스킬 보여준 사람"은 기억됩니다.

### 4-4. DB 스키마 (신규)

```sql
create table portfolio_skills (
  id            bigserial primary key,
  name          text not null,           -- 'HTML'
  tagline       text,                    -- '구조를 세우는 기본 재료'
  level         text not null,           -- '상' | '중' | '하'
  project_count int  default 0,
  sort_order    int  default 0,
  is_published  boolean default true,
  updated_at    timestamptz default now()
);
```

`updated_at`을 두면 **"마지막 갱신: 2026. 09. 03."** 표기가 가능합니다. 살아있는 페이지라는 증거가 됩니다.

## 5. 전체 디자인 방향

### 5-1. 컬러 팔레트 — 메인 4색

| 역할 | Hex | 이름 | 사용처 |
|---|---|---|---|
| **베이스** | `#0B0B0B` | Soft Black | 전체 배경 (밤하늘) |
| **시그니처** | `#DDFF50` | Neon Lime | 오로라 코어 · CTA · 활성 상태 |
| **서브** | `#ECFF9B` | Pale Lime | **연노랑 오로라** · 강조 텍스트 |
| **악센트** | `#CAB8F6` | Lavender | 오로라 끝단 · 별빛 · 보조 뱃지 |

**보조 (정보 코드용)**: `#7FE0C1` 민트 · `#F8F8F7` 별빛 화이트 · `#8A8A8A` 뮤티드

### 5-2. 가장 중요한 변경 — 라이트에서 다크로

현재 사이트는 **흰 배경**입니다. 오로라 컨셉은 **다크 배경**이 전제입니다.

```
현재:  bgPrimary: #FFFFFF   (밝은 배경 + 라임 색면)
변경:  bgPrimary: #0B0B0B   (밤하늘 + 라임 발광)
```

**이건 단순한 색 교체가 아니라 전면 재설계입니다.**
기존 `TONE_PRESETS` 5종, `SectionCard`, 대비비 계산이 전부 다시 잡혀야 합니다.

#### 권장 방식 — 다크 우선 + 라이트 토글

Loop Agency가 `LIGHT / DARK / SYSTEM` 3단 토글을 제공합니다. 같은 방식을 채택하되 **다크를 기본값**으로 둡니다.

| 이점 | 설명 |
|---|---|
| 컨셉 유지 | 오로라는 다크에서만 작동 |
| 실력 증명 | **테마 시스템 구현 = 프론트엔드 실무 역량.** 면접 소재 |
| 접근성 | 밝은 화면을 선호하는 사용자 배려 |
| 자산 재활용 | 기존 라이트 팔레트를 버리지 않고 라이트 모드로 살림 |

MUI는 `theme.palette.mode` 전환을 지원하므로, 기존 토큰 구조(CSS 변수 ↔ theme 1:1)를 유지한 채 확장할 수 있습니다.

#### 대비비 검증 (필수)

기존 코드가 이미 주석으로 대비비를 기록하는 좋은 습관을 갖고 있습니다. 다크 전환 후에도 유지합니다.

| 조합 | 대비비 | 판정 |
|---|---|---|
| `#DDFF50` on `#0B0B0B` | 17.3:1 | AAA |
| `#ECFF9B` on `#0B0B0B` | 15.8:1 | AAA |
| `#CAB8F6` on `#0B0B0B` | 10.2:1 | AAA |
| `#8A8A8A` on `#0B0B0B` | 5.1:1 | AA (본문 가능) |
| `#0B0B0B` on `#DDFF50` | 17.3:1 | AAA (CTA 버튼) |

다크 전환이 오히려 대비비를 좋게 만듭니다.
**라임은 밝은 배경보다 어두운 배경에서 훨씬 안전한 색입니다.**

### 5-3. 폰트 — 3종 (개성 있는 조합)

| 역할 | 폰트 | 이유 |
|---|---|---|
| **디스플레이** | `Noto Serif KR` (또는 `Gowun Batang`) | **명조 = 매거진의 언어.** 한글 헤드라인에 개성과 품격. 산세리프 일색인 개발자 포트폴리오 사이에서 즉시 구분됨 |
| **본문 / UI** | `Pretendard` | 한글 가독성 최상. **현재 사이트의 폰트 미지정 문제를 여기서 해결** |
| **모노** | `JetBrains Mono` | 메뉴판 "가격", 섹션 번호, 라벨. Loop이 `Fragment Mono` / `Geist Mono`를 쓴 것과 같은 용법 |

> NexStudio는 폰트 1종이었습니다. 여기서 3종을 쓰는 건 **매거진형 레이아웃이 세리프 ↔ 산세리프 대비를 전제**하기 때문입니다.
>
> 다만 규칙을 엄격히 지켜야 합니다.
>
> - 명조 → **헤드라인 전용** (본문에 쓰면 즉시 촌스러워짐)
> - 모노 → **숫자 · 라벨 전용**
> - 그 외 전부 Pretendard

**주의**: 폰트 3종은 용량이 큽니다. **한글 서브셋 + `font-display: swap` + preload**를 반드시 적용합니다.

### 5-4. 레이아웃 — 매거진형

```
┌────────────────────────────────────────────────────────┐
│ SOL / AURORA                              02 — SKILLS  │  ← 러닝헤드
├────────────────────────────────────────────────────────┤
│                                                        │
│   비대칭 그리드 (4:8, 7:5, 3:9 등 섹션마다 변주)         │
│   넓은 여백 · 큰 타이포 · 규칙적인 섹션 번호             │
│                                                        │
└────────────────────────────────────────────────────────┘
```

- **러닝헤드**: 모든 섹션 상단에 `좌: 사이트명 / 우: 번호 — 섹션명`. 잡지 페이지 헤더 감각
- **비대칭 그리드**: 매 섹션 같은 비율이면 매거진이 아니라 그냥 목록입니다.
  `size={{ xs: 12, md: 5 }}` / `md: 7` 식으로 변주
- **타이포 스케일**: NexStudio에게 배운 `clamp()` 적용 → 브레이크포인트 사이 점프 제거

```jsx
fontSize: 'clamp(2.4rem, 7vw, 5rem)'
```

### 5-5. 애니메이션 — "적당함"의 정의

| 구분 | 규칙 |
|---|---|
| **이징** | `cubic-bezier(.16, 1, .3, 1)` **단 하나로 통일** (NexStudio의 핵심 교훈) |
| **지속시간** | 등장 0.5~0.7s / 상태변화 0.2s. **NexStudio의 1.5초는 채택하지 않음** — 채용 담당자의 3분을 존중 |
| **등장** | `IntersectionObserver` + `opacity 0→1` + `translateY(20px→0)`, 스태거 60ms |
| **화려함 배분** | **Hero에만 집중.** 나머지 섹션은 절제 |
| **접근성** | `prefers-reduced-motion` 전면 대응 (이미 구현되어 있음 — 유지) |

> **왜 Hero에만 몰아주는가**
> 화려함을 전 구간에 뿌리면 정보 스캔이 느려지고, 결국 "보기엔 좋은데 읽기 힘든 사이트"가 됩니다.
> **첫 화면에서 확 잡고, 그 다음은 빠르게 읽히게** — 이게 신입 포트폴리오의 최적 배분입니다.

```
SOL / AURORA        Home   About   Works   Contact        [◐ 테마]
```

### 6-2. `/projects/:id` 케이스 스터디 구조

NexStudio의 7챕터를 **신입에 맞게 6챕터로 압축**하고, **NexStudio에 없는 항목 2개를 추가**합니다.

| # | 챕터 | 내용 |
|---|---|---|
| 01 | 무엇을 만들었나 | 한 줄 요약 + 라이브 / GitHub 링크 |
| 02 | 왜 만들었나 | 문제 정의 · 동기 |
| 03 | 어떻게 만들었나 | 기술 선택과 그 이유 |
| 04 | **막혔던 지점** ★ | 구체적 문제 + 해결 과정 — *NexStudio에 없음* |
| 05 | **숫자** ★ | Lighthouse · 번들 크기 · 구현 기능 수 — *NexStudio에 없음* |
| 06 | 다시 만든다면 | 회고 · 배운 점 |

> **04와 05가 신입의 무기입니다.**
> 04(막혔던 지점)는 **문제 해결 능력**을, 05(숫자)는 **정량 감각**을 보여줍니다.
> 완성작만 늘어놓는 포트폴리오와 여기서 갈립니다. NexStudio조차 이 둘이 없었습니다.

## 7. 차별화 전략

### 7-1. 경쟁 포지셔닝

```
                    화려함 ↑
                        │
        일반 신입        │     ★ SOL / AURORA
        (템플릿 사용)     │     (오로라 + 정직한 기록)
                        │
    ────────────────────┼────────────────────→ 정직함
                        │
        과장형           │      단순 나열형
        (스킬 90% 표시)  │      (README 수준)
                        │
                    화려함 ↓
```

**우상단(화려하면서 정직한)은 거의 비어 있는 구역입니다.**
화려한 포트폴리오는 대개 과장하고, 정직한 포트폴리오는 대개 밋밋합니다.

### 7-2. 차별화 요소 5개

| # | 요소 | 경쟁 우위 | 난이도 |
|---|---|---|---|
| 1 | **마우스 반응 오로라 + 별** | 시각적 각인. 기억에 남음 | 중 |
| 2 | **메뉴판 스킬 UI** | 발상의 독창성 + 정직함 | 하 |
| 3 | **`/design-system` 공개** | "디자인 감각"을 시스템으로 증명 | 하 |
| 4 | **방명록** (기존 자산) | 소통 능력의 실물 증거 · 인터랙티브 | 완료 |
| 5 | **레퍼런스 해체 노트** | "응용력"의 직접 증명 | 하 |

> **주목**: 5개 중 4개가 난이도 "하" 또는 이미 완료입니다.
> **가장 어려운 건 오로라 하나뿐**이고, 나머지는 **아이디어의 승리**입니다. 이게 좋은 기획의 조건입니다.

### 7-3. `/design-system` 페이지 — 숨은 킬러 카드

이미 `컬러 팔레트 디자인 시스템.md` 문서와 `src/theme.js` 토큰 체계가 **완성되어 있습니다.**
이걸 그냥 페이지로 만들어 공개하기만 하면 됩니다.

```
/design-system
  ├ Colors        토큰 스와치 + Hex + 대비비 표
  ├ Typography    3종 폰트 · 스케일 표
  ├ Components    버튼 · 카드 · 뱃지 · 입력폼 실물
  └ Principles    "파스텔은 장식이 아니라 정보 코드다" 등 원칙
```

**효과**: "깔끔한 디자인을 잘합니다"라는 문장 100개보다,
**대비비가 계산된 토큰 표 한 장**이 훨씬 강력합니다.
스타트업 팀 리드가 보면 "디자인 시스템을 이해하는 사람"으로 즉시 분류됩니다.

**투입 대비 효과가 이 기획서에서 가장 좋습니다.** 이미 있는 자산을 페이지로 옮기는 것뿐입니다.

| 플레이스홀더 섹션 | 0개 | **5개** | 육안 |
| 방명록 누적 | 20건 | **4건** | Supabase |

> **초기 청크 목표를 150KB → 185KB 로 수정한 이유 (P0 실측 결과)**
>
> 코드 스플리팅을 마친 뒤 실측한 초기 로딩 구성은 다음과 같습니다.
>
> | 청크 | gzip |
> |---|---|
> | `vendor-mui` | 91.3KB |
> | `vendor-react` | 69.5KB |
> | `vendor` (아이콘 외) | 14.8KB |
> | 앱 엔트리 + 라우트 | 6.2KB |
> | **초기 합계** | **약 182KB** |
>
> React 19 + MUI 만으로 이미 **160.8KB** 입니다. 이게 현재 스택의 물리적 하한이고,
> 150KB 는 MUI 를 걷어내야만 도달 가능한 수치였습니다. 잘못 잡은 목표였습니다.
>
> 대신 **실제 체감에 영향을 주는 부분은 확보했습니다.**
> `@supabase/supabase-js`(52.6KB)와 Contact 섹션(4.2KB)을 `IntersectionObserver` 로
> 스크롤이 닿을 때 내려받도록 미뤄, 첫 화면 부담에서 **56.8KB 를 덜어냈습니다.**
> (235KB → 182KB, **23% 감소**)

> 이 표 자체를 `/design-system` 하단에 공개하는 것도 좋은 수입니다.
> "나는 내 사이트를 숫자로 관리한다"는 메시지가 됩니다.
